2. ARCHITECTURE OVERVIEW
================================================================================

The system follows a CLIENT-SIDE ONLY architecture:
- NO server-side API routes or backend server
- ALL business logic runs in the browser
- Firebase SDK is used directly from client components
- Firestore Security Rules enforce authorization on the database level
- Authentication is handled by Firebase Auth (email/password)
- Real-time data via Firestore onSnapshot listeners
- Static export (output: "export" in next.config.ts)

4. AUTHENTICATION & AUTHORIZATION SYSTEM
================================================================================

AUTHENTICATION FLOW:
────────────────────
1. User visits "/" → Immediately redirected to "/login" (server-side redirect)
2. Login Page (/login):
   - User enters email + password
   - Firebase Auth signInWithEmailAndPassword() is called
   - On success → redirect to "/dashboard"
   - On failure → error message displayed
   - "Forgot Password" → Firebase sendPasswordResetEmail()
   
3. Register Page (/register):
   - ONLY for creating Admin accounts
   - Creates Firebase Auth user + Firestore "users" document (role: "Admin")
   - Signs out immediately after creation → redirects to "/login"
   - Employee accounts are created by Admin/HR via AddEmployeeModal

4. AuthProvider (Context):
   - Wraps entire dashboard layout
   - Listens to Firebase onAuthStateChanged
   - When user is authenticated:
     a. Fetches user profile from Firestore "users/{uid}"
     b. If not found, checks legacy "Users/{uid}" collection and auto-migrates
     c. If Admin/HR, performs background sweep to migrate all legacy "Users" docs
   - Provides: { user, profile, loading } via React Context

5. ProtectedRoute (Guard):
   - Wraps dashboard children
   - If not loading and no user/profile → redirect to "/login"
   - If user lacks permission for current route → redirect to "/dashboard" + toast error
   - Role checks:
     a. /dashboard/employees → requires Admin, HR, or OPS_HR
     b. /dashboard/departments → requires Admin only

EMPLOYEE REGISTRATION BY ADMIN (Key Pattern):
─────────────────────────────────────────────
- Uses a SECONDARY Firebase App instance so the currently logged-in Admin is NOT logged out
- Function: registerEmployeeByAdmin() in lib/auth.ts
- Creates: Firebase Auth account + Firestore "users/{uid}" document
- Signs out of secondary auth immediately after creation

REDIRECTION FLOWS:
──────────────────
1. Unauthenticated user → ANY /dashboard/* route:
   ProtectedRoute detects no user → router.push("/login")

2. Already authenticated user → /login or /register:
   Login/Register pages detect user exists → router.replace("/dashboard")

3. Employee → /dashboard/employees:
   ProtectedRoute detects unauthorized → router.replace("/dashboard") + toast error

4. Non-Admin → /dashboard/departments:
   ProtectedRoute detects unauthorized → router.replace("/dashboard") + toast error

5. Root "/" → /login:
   Server-side redirect in app/page.tsx

6. After successful login:
   router.push("/dashboard")

7. After successful admin registration:
   router.push("/login") (signs out first)

8. After logout:
   router.push("/login")

7. FIRESTORE DATABASE SCHEMA (ALL COLLECTIONS)
================================================================================

COLLECTION: users (Document ID = Firebase Auth UID)
─────────────────────────────────────────────────────
{
  uid: string,              // Firebase Auth UID
  fullName: string,         // "Mohammed Hamzah Saiyed"
  email: string,            // "hamzah@vectragroup.com"
  role: string,             // "Admin" | "HR" | "OPS_HR" | "Employee" | "MARKETING" | "SALES" | "IT"
  status: string,           // "Active" (only set for Admin on register)
  employeeId: string,       // "VG001" (optional, set for employees)
  jobRole: string,          // "ML Engineer" (optional)
  designation: string,      // "Manager" | "Intern" | etc.
  department: string,       // (optional, set on employee profile)
  phone: string,            // (optional, set in settings)
  timezone: string,         // "Asia/Kolkata" (default)
  aadhar: string,           // 12-digit Aadhar number (optional, set in documents page)
  pan: string,              // 10-char PAN number (optional)
  bankAccountName: string,  // Bank account holder name (optional)
  bankDetails: string,      // Account number + IFSC (optional)
  notificationsEmail: bool, // Notification preference
  notificationsLeave: bool, // Notification preference
  notificationsPayroll: bool, // Notification preference
  createdAt: Timestamp      // Server timestamp
}

COLLECTION: Users (LEGACY - capital U)
──────────────────────────────────────
Same schema as "users". Auto-migrated to "users" when Admin/HR logs in.

COLLECTION: attendance (Document ID = "{userId}_{YYYY-MM-DD}")
──────────────────────────────────────────────────────────────
{
  userId: string,           // Firebase Auth UID
  fullName: string,         // Employee name
  role: string,             // Employee role (optional)
  date: string,             // "2026-08-05" (YYYY-MM-DD)
  checkInTime: Timestamp,   // Firebase Timestamp (null if not checked in)
  checkOutTime: Timestamp,  // Firebase Timestamp (null if not checked out)
  status: string,           // "Present" | "Checked In" | "Absent" | "On Leave" | "Week Off"
  workingSeconds: number    // Total seconds worked
}
IMPORTANT: Date calculation uses a SHIFT-BASED logic.
  - Shift starts at 7:30 PM (19:30)
  - Any time before 7:30 PM belongs to PREVIOUS day's shift
  - e.g., 2:00 AM on Aug 6 → belongs to Aug 5 shift

COLLECTION: leave_requests (Auto-generated Document ID)
─────────────────────────────────────────────────────────
{
  userId: string,           // Firebase Auth UID
  fullName: string,         // Employee name
  department: string,       // Employee department
  role: string,             // Employee role (optional)
  leaveType: string,        // "Casual Leave" | "Sick Leave" | "Earned Leave" | etc.
  startDate: string,        // "2026-08-10" (YYYY-MM-DD)
  endDate: string,          // "2026-08-12" (YYYY-MM-DD)
  days: number,             // Number of leave days
  reason: string,           // Leave reason text
  status: string,           // "Pending" | "Approved" | "Rejected"
  appliedOn: Timestamp      // When the leave was applied
}

COLLECTION: salary_structures (Document ID = userId)
────────────────────────────────────────────────────
{
  userId: string,
  grossSalary: number,      // e.g., 50000
  travelAllowance: number,  // e.g., 2000
  otherDeductions: number,  // e.g., 500
  otherAllowances: number,  // e.g., 1000
  updatedAt: Timestamp
}

COLLECTION: payrolls (Document ID = "{userId}_{year}_{month}")
──────────────────────────────────────────────────────────────
{
  userId: string,
  employeeName: string,
  employeeId: string,
  jobRole: string,
  department: string,
  dateOfJoining: string,
  bankName: string,
  division: string,
  daysWorked: number,
  month: number,            // 1-12
  year: number,             // e.g., 2026
  
  // Earnings Breakup
  grossSalary: number,
  basic: number,            // 50% of gross
  hra: number,              // 20% of gross
  travelAllowance: number,
  specialAllowance: number, // gross - basic - hra - travel
  otherAllowances: number,
  incentives: number,
  totalEarnings: number,    // gross + otherAllowances + incentives
  
  // Deductions
  lopDays: number,          // Loss of Pay days
  lopDeduction: number,     // (gross/daysInMonth) * lopDays
  taxDeduction: number,     // Professional Tax (default 200)
  incomeTax: number,
  providentFund: number,
  otherDeductions: number,
  totalDeductions: number,

Salary Calculation Logic (lib/payroll.ts):
  INPUT: grossSalary, travelAllowance, lopDays, daysInMonth, otherDeductions,
         otherAllowances, incentives, professionalTax, incomeTax, providentFund
  
  CALCULATION:
    basic = grossSalary × 50%
    hra = grossSalary × 20%
    specialAllowance = grossSalary - basic - hra - travelAllowance (min 0)
    totalEarnings = grossSalary + otherAllowances + incentives
    perDaySalary = grossSalary ÷ daysInMonth
    lopDeduction = perDaySalary × lopDays
    totalDeductions = lopDeduction + professionalTax + incomeTax + providentFund + otherDeductions
    netSalary = totalEarnings - totalDeductions

  DEFAULTS:
    Professional Tax = ₹200 (fixed)
    Mode of Payment = "Bank Transfer"

10. DATA FLOW DIAGRAMS (TEXT-BASED)
================================================================================

EMPLOYEE CHECK-IN FLOW:
───────────────────────
Employee clicks "Check In"
  │
  ├─► getLocalDateString() → determines shift date (7:30 PM cutoff)
  │
  ├─► Generate docId: "{userId}_{dateStr}"
  │
  ├─► Check if doc exists in "attendance" collection
  │   ├─ YES → Return existing record (already checked in)
  │   └─ NO  → Create new record:
  │            {checkInTime: now, status: "Checked In", workingSeconds: 0}
  │
  ├─► Start 60-second interval timer
  │   └─► Every 60s: updateWorkingSeconds(docId, elapsed)
  │
  └─► UI shows live timer counting up


EMPLOYEE CHECK-OUT FLOW:
────────────────────────
Employee clicks "Check Out"
  │
  ├─► Calculate final workingSeconds
  │
  └─► updateDoc("attendance/{docId}"):
      {checkOutTime: now, status: "Present", workingSeconds: final}


LEAVE APPLICATION FLOW:
───────────────────────
Employee submits leave form
  │
  ├─► applyLeave() → addDoc("leave_requests")
  │   {status: "Pending", appliedOn: now}
  │
  └─► HR sees in real-time via listenToPendingLeaves()
      │
      ├─► HR clicks "Approve"
      │   └─► updateDoc("leave_requests/{id}", {status: "Approved"})
      │
      └─► HR clicks "Reject"
          └─► updateDoc("leave_requests/{id}", {status: "Rejected"})
          
      Employee sees status change in real-time via listenToUserLeaves()


PAYROLL GENERATION FLOW:
────────────────────────
HR opens GeneratePayrollModal for employee
  │
  ├─► getSalaryStructure(userId) → reads "salary_structures/{userId}"
  │
  ├─► HR enters: month, year, lopDays, taxes, incentives
  │
  ├─► calculateSalaryBreakup() → pure calculation:
  │   basic(50%), hra(20%), specialAllowance, earnings, deductions, netSalary
  │
  ├─► generatePayroll() → setDoc("payrolls/{userId}_{year}_{month}")
  │
  └─► PDF export via PayslipDocument → html2canvas → jsPDF


ANNOUNCEMENT CREATION FLOW:
────────────────────────────
Admin/HR creates announcement
  │
  ├─► addDoc("announcements") with {pinned, archived: false}
  │
  ├─► Fetch all users from "users" collection
  │
  ├─► For each user (except author):
  │   └─► createNotification(uid, "New Announcement: {title}", "announcement")
  │       └─► addDoc("notifications")
  │
  └─► All users see:
      ├─► Real-time announcement in announcements page
      ├─► Notification bell badge in Navbar
      └─► Unread count badge on Sidebar


DOCUMENT UPLOAD FLOW:
─────────────────────
User clicks Upload
  │
  ├─► Select scope: "personal" or "company" (Admin/HR can choose)
  │
  ├─► uploadBytes() → Firebase Storage
  │   path: "documents/{scope}/{userId}_{timestamp}_{filename}"
  │
  ├─► getDownloadURL() → get public download link
  │
  └─► addDoc("documents") with metadata + storageUrl + storagePath

13. STATE MANAGEMENT
================================================================================

The app uses REACT CONTEXT for global state, NOT Redux or Zustand.

Global Contexts:
  1. AuthContext (AuthProvider):
     - user: Firebase User | null
     - profile: UserProfile | null (from Firestore)
     - loading: boolean
     
  2. SidebarContext (SidebarProvider):
     - isOpen: boolean
     - toggleSidebar: () => void

All other state is LOCAL COMPONENT STATE (useState).
No centralized store for module data.

Real-time Data Pattern:
  - Each page/component subscribes to Firestore via onSnapshot in useEffect
  - Cleanup: unsubscribe returned from onSnapshot called in useEffect cleanup
  - Data is stored in local component state
  - No caching layer between components

15. KEY BUSINESS LOGIC
================================================================================

1. SHIFT-BASED DATE CALCULATION:
   - Function: getLocalDateString() in lib/attendance.ts
   - Before 7:30 PM (19:30) → previous day's date
   - At/After 7:30 PM → current day's date
   - Purpose: Night shift workers who check in late evening

2. SALARY BREAKUP FORMULA:
   basic = 50% of gross
   hra = 20% of gross
   specialAllowance = max(0, gross - basic - hra - travel)
   totalEarnings = gross + otherAllowances + incentives
   perDaySalary = gross / daysInMonth
   lopDeduction = perDaySalary × lopDays
   totalDeductions = lopDeduction + professionalTax + incomeTax + PF + otherDeductions
   netSalary = totalEarnings - totalDeductions

3. SECONDARY APP PATTERN (Employee Registration):
   - Admin creates employee → must not log out Admin
   - Solution: initializeApp(config, 'SecondaryApp')
   - Creates auth account on secondary instance
   - Admin's session on primary instance unaffected
   - Secondary auth signed out immediately after

4. LEGACY DATA MIGRATION:
   - Old collection: "Users" (capital U)
   - New collection: "users" (lowercase)
   - Migration: On login, if doc not found in "users", checks "Users"
   - Auto-copies to "users" and deletes from "Users"
   - Admin/HR login triggers batch migration of ALL remaining legacy docs

5. DOCUMENT VISIBILITY:
   - Admin/HR: sees ALL documents
   - Employee: sees company-scoped docs + own personal docs
   - Filter applied client-side after fetching all docs

6. ANNOUNCEMENT NOTIFICATIONS:
   - On create: iterates ALL users → creates individual notification per user
   - Potential N+1 problem with large user base

1. NO SERVER-SIDE LOGIC:

6. ONBOARDING NOT IN SIDEBAR:
   - Onboarding page exists but is NOT listed in sidebar navigation
   - Must be accessed via direct URL

7. REDUNDANT FIRESTORE READS:
   - Multiple components listen to same collections independently
   - No shared data layer or caching
